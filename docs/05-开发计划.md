## 一、总览

### 1.1 最终目标

打开网页就能看到当周课表；到点电脑会弹提醒。

### 1.2 技术栈（照 01 文档，不再讨论）

| 项目 | 选择 |
| --- | --- |
| 后端 | Python 3 + Flask |
| 数据库 | SQLite（`../data/class_schedule.db`） |
| 前端 | 原生 HTML / CSS / JavaScript |
| 虚拟环境 | 项目内 `venv` |
| 访问方式 | 局域网（电脑跑服务，手机连同一个 WiFi） |
| 提醒 | 后台常驻程序 + Windows 系统通知 |

### 1.3 施工总原则

1. **一步一跑**：每做完一个小任务，程序都要能起来、能看效果。不允许「写一大坨再一起调」。
2. **一步一提交**：每个任务做完就提交一次，方便随时回退到上一个能跑的版本。
3. **表结构一次定死**：照 03 文档建三张表，之后只加字段，不推翻重来。
4. **每步都摸一下手机**：需求要求手机能看，所以每个页面做完都顺手在手机上开一次。
5. **界面不许自由发挥**：颜色、按钮样式、弹窗规矩全按 02 文档。

### 1.4 阶段一览

| 阶段 | 名字 | 做什么 | 做完能得到什么 |
| --- | --- | --- | --- |
| 阶段 0 | 起骨架 | 虚拟环境 + Flask 能打开一个页面 + 数据库建好表 | 环境通了，但页面上什么都没有 |
| **阶段 1** | **MVP** | 学期/课程能增删改 + 课表页显示当周课表 | **自己就能用了**（能看课、能录课） |
| 阶段 2 | 提醒 | 后台程序常驻 + 到点弹 Windows 通知 | 上课前会提醒你 |
| 阶段 3 | 打磨 | 冲突检测、手机端细节、异常处理 | 顺手、不出洋相 |

## 三、阶段 1 · MVP 开发（重点）

### 3.1 MVP 是什么

用一句话说：**我自己打开网页，能看到这周的课；能把课录进去、改、删。**

就这三件事。提醒、冲突检测这些，都排在 MVP 后面。

### 3.2 MVP 的边界（哪些做、哪些先不做）

| 功能 | 进 MVP？ | 说明 |
| --- | --- | --- |
| 学期：新增 / 列表 / 删除 / 设为默认 | ✅ 进 | 没有学期就没法排课 |
| 学期卡片点「设置」进入课程设置页 | ✅ 进 | 录课的入口 |
| 课程：增 / 删 / 改（8 个属性） | ✅ 进 | 核心 |
| 课表页：当周 7 列 + 时间轴渲染、方块、点方块弹窗 | ✅ 进 | 核心 |
| 课表页：「第 x 学期」「第 x 周」 | ✅ 进 | 周次算法必须这时就有 |
| 空态（没默认学期）+「前往设置」按钮 | ✅ 进 | 第一次打开就是这个页面 |
| 日期不在学期范围内 → 提示「不在学期范围内」 | ✅ 进 | 放假时会看到 |
| 左侧菜单栏（桌面常驻 + 可收起；手机 ☰ 抽屉） | ✅ 进（基础版） | 抽屉的动画细节可以晚点调 |
| 时间冲突检测 + 卡片标红 | ❌ 不进 | 放阶段 3（已拍板）；MVP 里没有「冲突」这个概念 |
| 提醒程序（notifier） | ❌ 不进 | 阶段 2 整个一块（已拍板：不提前） |
| 部署公网 / 登录 / 多用户 | ❌ 不做 | 01 文档已定不做 |

### 3.3 MVP 任务清单（按建议顺序）

| 编号 | 任务 | 涉及文件 | 验收（怎么算做完） |
| --- | --- | --- | --- |
| M1 | 设置 → 学期：学期列表 + 新增弹窗 + 删除确认框 + 设为默认 | `../app.py`、`models.py`、`templates/` | 加两个学期、设默认、删一个，刷新后状态还在；库里 `is_default=1` 的**永远只有一个** |
| M2 | 课程设置页的入口与页头：从学期卡片「设置」进去；顶部显示该学期序号 + 起止日期且可改；**左侧菜单不点亮任何一项** | `../app.py`、`templates/` | 从学期卡片能进、能改回日期；此时菜单栏没有任何高亮 |
| M3 | 课程卡片：新增 / 修改 / 删除 + 左侧颜色圆 + 8 条属性表单 + 删除确认 | `../app.py`、`models.py`、`templates/` | 建一门「周一+周三」的课，卡片立刻出现、信息全对，能改能删 |
| M4 | 周次计算（纯算法，先写测试） | `../schedule.py` | 用 03 文档的算例自测：学期 2026-09-01 开始 → 2026-10-15 是**第 7 周**；周日开学那种也要对 |
| M5 | 课表页渲染：从默认学期取当周课程，按 03 文档第六节的坐标算法画方块（y=时间比例，x=周几，7 列，不画轴线、不写时间刻度） | `../app.py`、`schedule.py`、`templates/static` | 同一门课在正确的列、方块高度和时长成比例；切换周次轴不变 |

| M8 | 手机端适配：< 768px 菜单变抽屉（☰）、7 列压缩、课名适当缩短；课表页不可拖动缩放 | `../static/css`、`templates/` | 手机上：7 列都在、点方块能出弹窗、双手缩放无效 |
| M9 | **MVP 总验收**（下面 3.4 的三个场景） | — | 三个场景全过，打 tag `v0.1-mvp` |

### 3.4 MVP 验收（你自己点一遍就算过）

**场景 A · 第一次用**
没有学期 → 课表页提示「你还没有设置默认学期」→ 点「前往设置」→ 加「第 1 学期」并设为默认 → 回课表页看到「第 1 学期 / 第 x 周」。

**场景 B · 录课**
学期卡片点「设置」→ 加 3 门课（其中一门选「周一 + 周三」两个周几）→ 卡片当场出现 → 回课表页，方块出现在对应的列上。

**场景 C · 手机上**
手机打开同一地址 → 看到一样的课表 → 点方块看到老师 / 时间 / 地点。

> 场景 A、B、C 全过 = MVP 完成。这时候你已经可以拿它当自己的课表用了。

## 六、风险与注意

| 风险 | 会怎样 | 对策 |
| --- | --- | --- |
| 手机连不上（不同 WiFi / 防火墙拦了） | 手机上打不开课表 | 先用电脑验证功能；连不上先 `ipconfig` 看 IP、确认同一 WiFi；必要时给 python 加防火墙例外（需要你在弹窗点确认） |
| y 轴范围随课程变化 | 方块位置会跳 | 03 文档已定「同一学期固定范围」，实现时只算一次 |
| 提醒重复弹 | 一天弹好几遍，很烦 | 已触发记录（内存里）；程序重启后可能重弹一次，可接受 |
| 一个人做太慢 | 拖成烂尾 | 每个任务都切到「能照着做」的粒度，可以丢给 AI 写，你只做决定和验收 |

> **R4 的说明（2026-10-16 做完时记）**：**实测通过**。造一门「2 分钟后上课」的课 + 一条提醒，让 notifier 真跑：
> 14:49 准点触发一次、不重复、合并成一条、正文按 04 文档第四节拼，**横幅真的出现在屏幕右下角**（抓屏确认）。

> 结果是所有 toast 被**静默丢弃**（`Show()` 照样返回成功、托盘气泡也不显示、通知中心历史恒为 0）。
> **修法**（不用管理员、不用重启）：
> 1. `Stop-Service WpnUserService_<你的实例名>`
> 2. 把 `%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db{,-shm,-wal}` 改名备份
> 3. `Start-Service WpnUserService_<你的实例名>`，平台会重建库，立刻恢复
>
> **以后要是又收不到通知，先试这一招。**

> **P2 的说明（2026-10-16 做完时记）**：顺手挖出一个 Windows 上真会坑人的事 ——
> **Werkzeug 的开发服务器默认开着 SO_REUSEADDR，而 Windows 的 SO_REUSEADDR 允许两个进程同时绑同一个端口**
> （跟 Linux 不一样）。也就是说你手抖启动第二个 `../app.py` 时，它 **不会报错**，会悄悄起来和第一个抢请求。
> 现在 `app.py` 启动前会先用 `SO_EXCLUSIVEADDRUSE` 探一次端口，占了就直说：
> 「启动失败：端口 5000 用不了……浏览器直接打开 http://127.0.0.1:5000 就能用」。
> 另外启动横幅现在会把 **本机局域网 IP 印出来**（手机直接照着敲），数据库文件坏了也会给一句人话而不是堆栈。
